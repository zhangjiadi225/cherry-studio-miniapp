# 模型布景

Cherry miniapp monorepo 中的独立产品 workspace。

打开就是一个纯黑背景的 3D 模型工作区，只显示位于世界坐标 `Y=0` 平面的网格辅助线，不创建实体地面、展台或内置模型。用户可以选择包含 GLB/glTF 及其贴图、二进制文件等依赖的模型目录，再选择本地效果方案完成布景；无需配置 AI，也不接入 MCP。

右侧面板提供“方案 / 对话 / 场景”三个 Tab（页签，即同一面板内切换的内容页），默认显示方案：柔光白棚、深色产品棚、黑金轮廓、冷蓝科技、透明素材，以及四个快捷机位、六种背景和三点灯光强度调节。卡片是风格示意，不是真实模型渲染图。应用方案会重设环境、地面、灯光、镜头与后期、关闭雾和天气；模型、材质、自定义灯光及动态行为保持不变。

本地操作生成确定性的 ScenePatch（场景增量修改计划），在当前版本令牌下经 Skenora 能力检查和校验后原子提交；一次点击或一次滑杆调节对应一个撤销步骤。保存内容包括 SceneDocument（场景文档）、最近本地操作的 JSON 与真实提交/画面更新结果。微调、AI 修改、撤销或重做后取消方案选中标记，不把自定义布景误标成完整预设。

Cherry AI 是可选增强。普通问题直接回复；明确的场景修改先经过产品策略与 Skenora 校验。镜头、环境、已有灯光和主体变换等低风险修改可自动提交，材质、场景效果、动态行为和删除等中高风险修改必须由用户确认。“场景”页提供真实层级树与节点属性。

场景文档与最近一次真实提交结果会随会话保存。应用重启后恢复环境、灯光、镜头、对象层级和其他场景设置；浏览器不能持久保存本地模型文件，因此历史模型会明确显示“待重新导入”，用户重新选择模型目录后才恢复主体修改能力。Flow（场景行为流程）、模型动画和镜头路径不会因 AI 修改而自动运行，只能通过视口中的“预览”按钮显式启动。

从 monorepo 根目录运行：

```bash
pnpm --filter @miniapps/model-stage dev
pnpm --filter @miniapps/model-stage build
pnpm --filter @miniapps/model-stage miniapp:pack
```

源码只通过公开包入口使用 foundation 或 Skenora。`@cherry-miniapp/*` 依赖由根 workspace 解析；`@skenora/sdk` 与 `@skenora/scene-plan` 固定使用 npm registry 中发布的 0.1.2。

当前“导出场景”仅导出 JSON，不含本地模型文件，也不是 PNG。透明素材方案设置透明背景并关闭地面，视口棋盘格只是透明辅助显示。真实光照效果仍受模型材质、尺寸、方向和设备能力影响，需在 Cherry Studio 中人工验收。构建、测试与 UI 验收不会自动执行。
