# 模型布景 / Model Stage

运行在 Cherry Studio 中的本地 3D 模型布景工具。导入 GLB/glTF 模型，选择灯光方案、镜头与环境氛围；不配置 AI 也能使用本地布景功能。

## 安装与兼容性

- 在线安装清单：GitHub Pages development 地址待启用；计划路径为 `https://zhangjiadi225.github.io/cherry-studio-miniapp/miniapps/model-stage/manifest.json`，当前不是有效安装链接。
- 应用 ID：`dev.cherrymini.model-stage`；当前版本以[包内清单](./public/manifest.json)为准。
- 需要提供 Local MiniApp（本地小应用）能力的 Cherry Studio；已验收版本待记录，不将开发分支兼容基线当作发布版验收结果。
- AI 对话和场景修改需要在 Cherry Studio 中配置可用模型；本地导入、方案与手动调节不依赖模型可用性。

`public/manifest.json` 不是在线安装地址。手动触发仓库的 GitHub Pages 工作流后，将生成本应用独立的 HTTPS 发布清单和 `.miniapp` 安装包，不需要安装同仓库的其他应用；Pages 未启用或工作流未成功时不要使用上述计划地址。维护者见[社区发布指南](../../foundation/specs/community-publishing.md)。

## 功能与保存边界

打开就是一个纯黑背景的 3D 模型工作区，只显示位于世界坐标 `Y=0` 平面的网格辅助线，不创建实体地面、展台或内置模型。用户可以选择包含 GLB/glTF 及其贴图、二进制文件等依赖的模型目录，再选择本地效果方案完成布景；无需配置 AI，也不接入 MCP。

右侧面板提供“方案 / 对话 / 场景”三个 Tab（页签，即同一面板内切换的内容页），首次默认显示方案，之后恢复上次页签：柔光白棚、深色产品棚、黑金轮廓、冷蓝科技、透明素材，以及四个快捷机位、六种背景和三点灯光强度调节。卡片是风格示意，不是真实模型渲染图。应用方案会重设环境、地面、灯光、镜头与后期、关闭雾和天气；当前会话的模型、材质、自定义灯光及动态行为保持不变。

本地操作生成确定性的 ScenePatch（场景增量修改计划），在当前版本令牌下经 Skenora 能力检查和校验后原子提交；一次点击或一次滑杆调节对应一个撤销步骤。SceneDocument（场景文档）只在当前会话完整存在；自动保存仅提取无需外部资源的布景参数，另存最近本地操作的 JSON 与真实提交/画面更新结果供查看。微调、AI 修改、撤销或重做后取消方案选中标记，不把自定义布景误标成完整预设。

Cherry AI 是可选增强。普通问题直接回复；明确的场景修改先经过产品策略与 Skenora 校验。镜头、环境、已有灯光和主体变换等低风险修改可自动提交，材质、场景效果、动态行为和删除等中高风险修改必须由用户确认。“场景”页提供真实层级树与节点属性。

v0.6.0 接入 Skenora 0.1.3 的可选粒子模块：“环境氛围”提供雨幕、飘雪、漂浮光点、关闭、0–2 倍密度和恢复默认。直接使用上游预设和随包贴图，不请求远程图片。切换或调密度沿用一次校验、一次提交和一次撤销的入口；只操作天气与应用专用漂浮实体，不删除模型或其他自定义粒子。雨雪即时生效，漂浮光点需要点击“预览”；停止预览不关闭雨雪。天气是局部视觉效果，不具备碰撞、积雪或湿润材质。AI 上下文也获得已注册贴图 ID 和原生预设字段，但仍按实际设备能力校验。

保存“布景工作台”，不恢复历史模型。重启恢复背景、灯光、地面、雾、天气、文档镜头、后期，以及页签和场景设置节点状态；模型文件、任意实体、材质及其绑定、Flow（场景行为流程）、动画、镜头路径和撤销历史只在当前会话存在。仅标准的应用漂浮预设可从保存的密度重建，不从存档加载整个粒子实体；它仍等待显式预览。视口手动旋转/缩放和临时取景不额外写回文档。重新导入使用新 ID，不沿用旧模型的变换或绑定。

存储升级到 v6，自动迁移 v5/v4/v3/v2。启动固定注册三张包内置粒子贴图，不读取旧模型资源表；允许恢复这些内置贴图的逻辑 ID。外部背景回退为纯色，外部环境贴图关闭，无法恢复贴图的天气关闭并提示重新选择氛围，不把缺失贴图误称为有效默认效果。无效设置按类别回退，其他有效设置保留。旧存档键保留作备份，成功写入 v6 后以 v6 为准。对话及修改记录仅供查看，不重放、不进入新会话的 AI 上下文；同一会话替换模型也会重新开始 AI 上下文。待确认提案和预览播放状态不保存。

## 权限与数据

当前包内清单声明以下权限：

| 权限 | 用途 |
| --- | --- |
| `ai.chat` | 用户发送对话时，通过 Cherry Studio 的模型生成回答或场景修改提案；必要时发送校验诊断请求修复 |
| `storage.*` | 应用范围的存储权限集合；当前通过读取和写入保存布景参数、界面状态及只读历史，不保存模型文件 |
| `file.save` | 用户点击“导出场景”时，先把场景 JSON 写入应用文件区 |
| `file.export` | 将上述 JSON 经宿主导出到用户选择的位置 |

模型导入通过用户主动选择文件目录完成。AI 请求会包含用户输入、近期对话与当前场景上下文（包括模型名称、场景层级和材质参数），交由 Cherry Studio 中配置的模型处理；不要把“本地布景”理解为启用 AI 后所有数据仍只在本机处理。当前未申请 `network.fetch`、通知或剪贴板权限，但这不等于宿主的 AI 调用不会联网。

模型文件仅在当前会话中使用，重启需重新导入；导出只包含场景 JSON，不包含模型文件，也不是 PNG。更完整的保存与恢复边界见上文。

## 本地开发

本应用是 monorepo 中的独立 workspace（由根目录统一管理依赖的应用目录）。从仓库根目录运行：

```bash
pnpm --filter @miniapps/model-stage dev
pnpm --filter @miniapps/model-stage build
pnpm --filter @miniapps/model-stage miniapp:pack
```

源码只通过公开包入口使用 foundation 或 Skenora。`@cherry-miniapp/*` 依赖由根 workspace 解析；`@skenora/sdk` 与 `@skenora/scene-plan` 固定使用 npm registry 中发布的 0.1.3。粒子通过 `@skenora/sdk/particles` 接入，MCP/Node tooling 不进入浏览器依赖图。

当前“导出场景”仅导出 JSON，不含本地模型文件，也不是 PNG。透明素材方案设置透明背景并关闭地面，视口棋盘格只是透明辅助显示。真实光照效果仍受模型材质、尺寸、方向和设备能力影响，需在 Cherry Studio 中人工验收。构建、测试与 UI 验收不会自动执行。
